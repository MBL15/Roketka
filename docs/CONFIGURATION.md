# Настройка игры без изменения кода

Вся игровая экономика вынесена в один файл — `config/game-config.yaml`. Код
пересобирать не нужно, перезапускать сервер не нужно.

---

## 1. Два равнозначных способа

### Файл

Откройте `config/game-config.yaml` в любом редакторе, измените значение,
сохраните. Сервер сверяет время изменения файла раз в секунду и перечитывает
его автоматически.

В Docker-стенде каталог `config/` смонтирован в контейнер как bind mount, так
что правка на хосте немедленно видна внутри.

### Админ-панель

<http://localhost:8080/#admin> — все параметры разложены по вкладкам с
пояснениями. Кнопка «Проверить» прогоняет валидацию, не применяя изменений;
«Сохранить и применить» записывает их в тот же самый файл.

Панель записывает YAML **вместе с комментариями**: файл остаётся
самодокументированным, и после сохранения из UI его по-прежнему удобно
редактировать руками. Оба способа полностью равнозначны.

---

## 2. Порядок применения

```
изменение файла или сохранение из админки
   ↓  (не более 1 секунды)
разбор YAML
   ↓
валидация
   ├─ ошибок нет  → конфигурация применена
   │                ├─ новые раунды идут по новым параметрам
   │                └─ уже летящие доигрываются по своим (снимок при старте)
   └─ ошибки есть → изменения ОТКЛОНЕНЫ, работает предыдущая версия,
                    текст ошибок в GET /api/admin/config/status и в админке
```

Два следствия, о которых стоит помнить:

1. **Сломать игру правкой файла нельзя.** Некорректная конфигурация не
   применяется, сервер продолжает работать на последней рабочей.
2. **Изменение не влияет на начатый раунд.** Каждый раунд хранит снимок
   параметров, с которыми он стартовал. Настройка не может изменить исход уже
   идущего полёта — ни случайно, ни намеренно.

Проверить текущее состояние:

```bash
curl -s http://localhost:8081/api/admin/config/status -H "X-Session-Token: $TOKEN"
```

```json
{
  "path": "/app/config/game-config.yaml",
  "writable": true,
  "loadedAt": "2026-09-11T10:14:02Z",
  "appliedRevisions": 3,
  "valid": true,
  "errors": [],
  "lastErrorAt": null
}
```

## 3. Справочник параметров

### Общее

| Параметр | Тип | Допустимо | Назначение |
| --- | --- | --- | --- |
| `version` | int | ровно `1` | версия схемы; чужой конфиг будет отклонён |

### `themes.<green\|red>` — базовые параметры

Ровно два ключа тем. Названия менять нельзя: с ними связаны требования к числу
уровней (green → 9, red → 12).

| Параметр | Тип | Допустимо | Назначение |
| --- | --- | --- | --- |
| `gameId` | строка | непустая | идентификатор версии игры (`game_id`) |
| `gameName` | строка | непустая | название на экране выбора темы (`game_name`) |
| `gameType` | строка | непустая | тип игры (`game_type`) |
| `active` | bool | — | `false` — тема недоступна для новых раундов (`is_active`) |

### `themes.<...>.math` — математическая модель

| Параметр | Тип | Допустимо | Что меняет |
| --- | --- | --- | --- |
| `alpha` | double | 0.5 … 3.0 | форма хвоста распределения. Больше — шар лопается раньше. **При 1.0 RTP не зависит от момента выхода** |
| `houseEdge` | double | 0 … 0.30 | доля мгновенных крахов; RTP базовой ставки = `1 − houseEdge` |
| `minCrashMultiplier` | double | ≥ 1.0 | минимально возможная точка краха |
| `maxMultiplier` | double | > min | жёсткий потолок коэффициента |
| `multiplierGrowthRate` | double | > 0 | темп роста `m(t) = exp(rate · t)`; определяет, сколько секунд есть на решение |
| `fps` | int | 5 … 60 | частота серверных тиков. На плавность картинки **не влияет**: клиент рисует 60 кадров сам |
| `delta` | double | > 0 | шаг округления коэффициента, всегда вниз |
| `maxFlightSeconds` | int | 5 … 600 | предохранитель против «вечного» раунда |

Совместное ограничение: `alpha + max(alphaShift)` должно попадать в 0.5 … 4.0.

### `themes.<...>.levelMultipliers`

Строго возрастающий список порогов. Длина задаёт число уровней и проверяется:
green → ровно 9, red → ровно 12. Первый элемент строго больше 1.0, последний не
больше `maxMultiplier`.

Первый уровень разблокирует кнопку «Забрать», поэтому его стоит держать заметно
ниже медианы точки краха (`(2·(1−edge))^(1/alpha)`, для зелёной темы 1.92x) —
иначе большинство раундов закончится раньше, чем игрок получит право на
решение.

### `themes.<...>.lootProbabilities`

Веса уровней в лотерее «где спрятан бустер» — это `line_1_loot_prob` …
`line_N_loot_prob` из постановки. Длина равна числу уровней, сумма может быть
любой положительной: веса нормируются автоматически.

Конкретный уровень раунда игроку **не раскрывается** до срабатывания (иначе
выбор момента выхода становится выигрышной стратегией — разбор в
[MATH_MODEL.md](MATH_MODEL.md#что-такое-скрытая-позиция-бустера-и-зачем-она-нужна)).
Клиент получает только нормированное распределение и подсвечивает им лестницу
уровней.

### `themes.<...>.boostTierValues`

Ровно 4 значения — `multiplier_tier_1_value` … `multiplier_tier_4_value`.
Первое всегда `1.0` (вариант без усиления), остальные положительные.

### `themes.<...>.betOptions`

Ровно 4 варианта — это фрагменты пазла на экране выбора ставки.

| Параметр | Тип | Допустимо | Назначение |
| --- | --- | --- | --- |
| `id` | int | уникальный | идентификатор варианта |
| `cost` | long | > 0 | стоимость в бонусных баллах |
| `boostTier` | int | 1 … 4 | ссылка на `boostTierValues` |
| `alphaShift` | double | ≥ 0 | надбавка к `alpha` именно для этого варианта |

### `themes.<...>.points`

| Параметр | Соответствие постановке | Назначение |
| --- | --- | --- |
| `perLine` | `points_per_line` | очки за каждый пройденный уровень |
| `cashoutBonus` | `points_cashout_bonus` | разово за успешную фиксацию |
| `boostBonusPerTier` | `points_xN_bonus` | 4 значения, за активацию бустера уровня N |

### `reward` — коллекция «Карта неба»

| Параметр | Допустимо | Назначение |
| --- | --- | --- |
| `enabled` | bool | выключает награду целиком |
| `collectionName` | непустая | название на экранах |
| `collectionSize` | 1 … 24 | фрагментов в коллекции |
| `guaranteedNewChanceOnWin` | 0 … 1 | шанс гарантированно нового фрагмента после выигрыша |
| `guaranteedNewChanceOnLoss` | 0 … 1 | то же после проигрыша |
| `duplicateCompensationPoints` | ≥ 0 | очки за дубликат |
| `completionBonusPoints` | ≥ 0 | очки за собранную коллекцию |
| `completionBonusBalance` | ≥ 0 | бонусные баллы за собранную коллекцию |

### `upsell` — «Закрепи успех»

| Параметр | Соответствие | Назначение |
| --- | --- | --- |
| `enabled` | — | выключает предложение |
| `minWinAmount` | `MIN_WIN_AMOUNT` | минимальный выигрыш для показа |
| `popupTimeoutSeconds` | `POPUP_TIMEOUT` | автозакрытие без реакции, 3 … 120 |
| `ticketPriceBonus` | — | цена билета в бонусных баллах |
| `maxTickets` | 1 … 50 | верхняя граница предложения |
| `winShare` | 0 … 1 | какую долю выигрыша предлагать обменять |

Число билетов: `clamp(round(выигрыш · winShare / ticketPriceBonus), 1, maxTickets)`,
затем урезается по фактическому балансу.

### `tournament`

| Параметр | Назначение |
| --- | --- |
| `enabled` | выключает рейтинг и таблицу |
| `name` | название турнира |
| `durationDays` | длительность, 1 … 365 |
| `liveRatingSize` | сколько элементов в строке над игровым экраном |
| `anonymizeNames` | маскировать первые 3 символа чужих имён |
| `simulation.enabled` | боты-соперники (для живой демонстрации рейтинга) |
| `simulation.botCount` | число ботов, 0 … 200 |
| `simulation.tickSeconds` | как часто боты набирают очки |
| `simulation.maxPointsPerTick` | максимум очков бота за тик |

### `session`

| Параметр | Назначение |
| --- | --- |
| `resultIdleTimeoutSeconds` | бездействие на экране результата до возврата к выбору темы |
| `onboardingHintSeconds` | длительность подсказки «Нажми Забрать» |
| `historySize` | длина общей истории раундов |
| `demoBonusBalance` | стартовый баланс новых и демонстрационных профилей |

## 4. Рецепты

### Сделать игру щедрее или жаднее

Меняйте **только** `houseEdge`: при `alpha = 1` он напрямую равен потере
игрока. `houseEdge: 0.02` → RTP 98%, `0.10` → 90%. Остальное трогать не нужно.

### Ускорить или замедлить раунд

`multiplierGrowthRate`. Время до коэффициента m считается как
`ln(m) / rate`. При 0.17/с до 2x проходит 4.1 секунды, при 0.34/с — 2.0.

### Сдвинуть «вкус» темы, не меняя отдачу

`alpha` выше 1 смещает выгоду к ранним выходам, ниже 1 — к поздним. Учтите:
при `alpha ≠ 1` RTP перестаёт быть плоским, и появляется оптимальная точка
выхода. Обязательно перепроверьте симулятором.

### Подбор alphaShift

Нужен после любого изменения `alpha`, `houseEdge`, `levelMultipliers` или
`lootProbabilities` в теме с бустерами.

1. Откройте админку → «Симулятор RTP».
2. Стратегия `LEVEL`, 50 000 раундов, фиксированный seed.
3. Прогоните для каждого уровня от 1 до N и запишите максимальный RTP по
   каждому варианту ставки.
4. Если максимум выше 0.94 — увеличьте `alphaShift` этого варианта; если ниже
   0.90 — уменьшите. Шаг 0.05 сдвигает RTP примерно на 0.03.
5. Повторяйте, пока максимумы всех четырёх вариантов не сойдутся в коридор
   0.90 … 0.94.

Симулятор умеет считать по черновику, поэтому подбор идёт без сохранения. Когда
результат устроит — «Сохранить и применить».

Строки с RTP ≥ 100% подсвечиваются красным: это значит, что вариант ставки
выгоден игроку.

### Отключить турнирных ботов

`tournament.simulation.enabled: false`. Живой рейтинг останется, но будет
показывать только реальных игроков.

### Выключить тему

`themes.red.active: false`. Тема исчезнет с экрана выбора, попытка начать в ней
раунд будет отклонена. Уже летящие раунды доиграются.

## 5. Проверка через API

```bash
TOKEN=$(curl -s -X POST http://localhost:8081/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"nickname":"expert","password":"expert"}' | jq -r .token)

# Текущая конфигурация
curl -s http://localhost:8081/api/admin/config -H "X-Session-Token: $TOKEN"

# Проверить, не применяя
curl -s -X POST http://localhost:8081/api/admin/config/validate \
  -H 'Content-Type: application/json' -H "X-Session-Token: $TOKEN" \
  -d @my-config.json

# Применить
curl -s -X PUT http://localhost:8081/api/admin/config \
  -H 'Content-Type: application/json' -H "X-Session-Token: $TOKEN" \
  -d @my-config.json

# Вернуть заводские значения
curl -s -X POST http://localhost:8081/api/admin/config/reset -H "X-Session-Token: $TOKEN"
```

Некорректная конфигурация возвращает `422` со списком ошибок на русском языке;
действующая при этом не меняется.
