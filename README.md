# Воздушный Шар — бонусная краш-игра для «Столото»

Рабочий прототип бонусной игры: игрок ставит бонусные баллы, следит за растущим
коэффициентом и успевает (или не успевает) забрать выигрыш до того, как шар
лопнет. Две темы, 9 и 12 уровней, бустеры, игровые очки, турнир, коллекционная
награда и апсейл лотерейных билетов.

Кейс «Воздушный шар», Чемпионат России 2026, дисциплина «Программирование
продуктовое», онлайн-этап.

## Быстрый запуск

Нужен только Docker (Desktop на Windows/macOS либо Docker Engine на Linux).
Ничего больше устанавливать не требуется: JDK, Maven и Node живут внутри
образов.

```bash
docker compose up --build
```

Если появляется **`permission denied`** при обращении к `/var/run/docker.sock`,
пользователь не в группе `docker` (типично для Linux). Один раз:

```bash
./scripts/setup-docker-access.sh
newgrp docker
```

Либо сразу запуск через обёртку (сама подберёт `sg docker` или `sudo`):

```bash
./scripts/docker-compose.sh up --build
```

Первая сборка занимает 5–8 минут (скачивание Maven- и npm-зависимостей),
последующие — меньше минуты.

| Что | Адрес |
| --- | --- |
| Игра | <http://localhost:8080> |
| Админ-панель | <http://localhost:8080/#admin> |
| Swagger UI | <http://localhost:8080/swagger-ui.html> |
| OpenAPI JSON | <http://localhost:8080/v3/api-docs> |
| API напрямую | <http://localhost:8081> |
| Проверка живости | <http://localhost:8081/actuator/health> |

Остановить: `docker compose down`. Удалить данные вместе с контейнерами:
`docker compose down -v`.

### Демонстрационные учётные записи

Создаются автоматически при первом старте, у всех ненулевой бонусный баланс
(5000 баллов, значение настраивается в конфигурации).

| Логин | Пароль | Назначение |
| --- | --- | --- |
| `demo` | `demo` | основной демонстрационный игрок |
| `expert` | `expert` | для прохождения проверочных сценариев |
| `judge` | `judge` | отдельный профиль, чтобы не мешать друг другу |

Учётные данные продублированы на экране входа и подставляются одним нажатием.
Регистрация нового игрока тоже доступна. Если баллы закончились, в шапке
появляется кнопка пополнения на 2000 — прототип не должен упираться в баланс.

## Стек

| Слой | Технология | Лицензия |
| --- | --- | --- |
| Backend | Java 21, Spring Boot 3.3 (Web, WebSocket, Data JPA, Validation) | Apache-2.0, GPLv2+CE |
| БД | H2 в файловом режиме (по умолчанию), опционально PostgreSQL 16 | MPL/EPL, PostgreSQL License |
| Документация API | springdoc-openapi 2.6 (Swagger UI) | Apache-2.0 |
| Frontend | React 18, TypeScript 5, Vite 5, Canvas 2D, Web Audio API | MIT |
| Отдача статики | nginx 1.27 | BSD-2-Clause |
| Сборка и запуск | Docker, Docker Compose | Apache-2.0 |

**Платного и проприетарного ПО в решении нет.** Лицензионные ключи, платные
подписки и закрытые SDK не используются, поэтому проверка и запуск не зависят
ни от одного вендора. Отдельно отмечу два решения в ту же сторону:

- никаких графических и анимационных библиотек — вся анимация это Canvas 2D и
  CSS, а все звуки синтезируются Web Audio API прямо в браузере, поэтому в
  репозитории нет ни одного бинарного ассета;
- никаких внешних сервисов: ни CDN, ни шрифтов из сети, ни телеметрии. Стенд
  полностью работоспособен без интернета после сборки образов.

## Проверочные сценарии

Все обязательные сценарии проходятся в интерфейсе без обращения к команде.

**1. Выбор ставки и старт раунда.** Войти как `demo/demo` → выбрать тему →
экран ставки показывает четыре фрагмента с ценой и условием бустера, число
уровней темы, кнопку «Правила игры» и историю раундов всех игроков. Выбрать
доступный фрагмент → «Начать» станет активной → нажать. Проигрывается анимация
наполнения шара, баланс уменьшается, открывается экран полёта.
Недоступный по балансу фрагмент помечен и при нажатии выдаёт «Не хватает
бонусов» — проверить можно на фрагменте за 500, предварительно потратив баланс.

**2. Успешный вывод выигрыша.** В полёте кнопка «Забрать» видна сразу, но
неактивна до прохождения первого уровня. После первого уровня нажать её:
коэффициент фиксируется, начисляется `ставка × коэффициент`, появляется
сообщение «Могли бы забрать больше», шар продолжает лететь. Экран результата
откроется только после краха и покажет выигрыш, коэффициент, максимум раунда,
очки и награду.

**3. Проигрыш.** Начать раунд и не нажимать «Забрать». Шар лопается, экран
результата сообщает о потере ставки и показывает коэффициент краха. Игровые
очки за пройденные уровни и фрагмент коллекции начисляются всё равно.

**4. Бустер.** Выбрать фрагмент с усилением ×2/×3/×4. На лестнице уровней
подсвечена «горячая зона» — вероятности положения бустера. Если шар долетит до
спрятанного уровня раньше, чем нажата «Забрать», экран вспыхивает, звучит
сигнал, коэффициент умножается, начисляются дополнительные очки. После фиксации
выигрыша бустер уже не срабатывает.

**5. Управление параметрами.** Два равнозначных способа, оба без правки кода:

- открыть <http://localhost:8080/#admin>, изменить, например,
  `points → perLine` у зелёной темы, нажать «Проверить», затем «Сохранить и
  применить». Следующий раунд начисляет новое количество очков;
- открыть `config/game-config.yaml` в любом редакторе, изменить то же значение и
  сохранить. Сервер подхватит файл за ~1 секунду.

Некорректное значение (например, 3 уровня вместо 9) отклоняется с понятным
текстом ошибки, а игра продолжает работать на предыдущей конфигурации.

Оценить влияние математических параметров одним раундом невозможно, поэтому в
админке есть Monte-Carlo симулятор: вкладка «Симулятор RTP» прогоняет десятки
тысяч раундов на текущих или ещё не сохранённых настройках.

**Дополнительные сценарии.** Живой рейтинг — строка над игровым экраном,
обновляется в реальном времени. Турнирная таблица — кнопка «Турнир» на экране
ставки: топ-3 закреплены сверху, остальные прокручиваются, ваша позиция
закреплена снизу. Апсейл — после выигрыша от 50 баллов, не более одного раза за
сессию.

## Разработка без Docker

Нужны JDK 21 и Node.js 20.

```bash
# Backend, порт 8081
cd backend
mvn spring-boot:run

# Frontend с горячей перезагрузкой, порт 5173
cd frontend
npm install
npm run dev
```

Dev-сервер Vite проксирует `/api`, `/ws` и Swagger на `http://localhost:8081`
(адрес переопределяется переменной `BALLOON_API`).

### Тесты

```bash
cd backend && mvn test
```

57 тестов: свойства распределения точки краха, равномерность и
воспроизводимость provably-fair генератора, валидация конфигурации,
сохранение комментариев при записи YAML, экономика на боевых параметрах
(ни одна стратегия выхода не обыгрывает заведение) и сквозные HTTP-сценарии 1–5.

Если локально нет JDK, тот же прогон запускается через Docker:

```bash
docker run --rm -v "$PWD:/work" -w /work/backend maven:3.9-eclipse-temurin-21 mvn -B test
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8080` | внешний порт интерфейса |
| `API_PORT` | `8081` | внешний порт backend |
| `BALLOON_CONFIG_PATH` | `/app/config/game-config.yaml` | путь к игровой конфигурации |
| `BALLOON_DATA_DIR` | `/app/data` | каталог файловой БД H2 |
| `SPRING_PROFILES` | `default` | `postgres` — переключение на PostgreSQL |
| `DEMO_BONUS_BALANCE` | `5000` | стартовый баланс демо-профилей |
| `SIMULATION_ENABLED` | `true` | боты-соперники в турнире |

Пример файла — `.env.example`.

### Запуск на PostgreSQL

```bash
docker compose --profile postgres up --build
SPRING_PROFILES=postgres docker compose up backend
```

Схема создаётся Hibernate автоматически.
